How the scan works
Every refresh first reads balanceOf(wallet) at one pinned Base block, so the live chain remains the authority. For this non-enumerable ERC-721, the first refresh builds a contract-wide ownership index by replaying standard Transfer events from deployment through the pinned block and stores only the current token → owner map locally in this browser. Later refreshes scan only blocks after the cached block, apply new transfers, select tokens whose cached owner is one of our wallets, and re-verify every selected token with ownerOf(). The cache is only an accelerator: expected balanceOf() and verified ownerOf() counts must match exactly or the refresh fails closed. “Rebuild full cache” discards no old cache until a fresh full index succeeds. Metadata is loaded after ownership is complete, with Blockscout fallback when tokenURI hosts block browser CORS. Artwork tries token metadata/IPFS first, then the local helper endpoint; the helper may resolve OpenSea/SeaDN media but never determines ownership. No signing, approvals, private keys, or transactions.

This tool is a local read-only viewer. The contract-wide ownership cache is stored only in this browser and is never treated as authority: every refresh reads live wallet balances and verifies the selected token owners on-chain at one pinned Base block. The first cache build can take about as long as the old full-history scan; later refreshes usually need only the blocks since the last cached block. Public RPC endpoints can be rate-limited, so the reader paces calls, retries transient 429/5xx errors, and fails closed on any ownership-count mismatch. Metadata/artwork are read separately from tokenURI with Blockscout media plus multi-gateway IPFS fallbacks. When those artwork URLs fail, the localhost helper resolves OpenSea/SeaDN display media and caches the actual image bytes on disk; it never participates in ownership decisions.
